# 본관 실내 확장

전체 가구의 표시는 `sprite-geometry.mjs`가 담당한다. 사각 가구는 알파 외곽에서 바닥 접점 3개를 측정하고, 상판/좌측면/우측면을 같은 셀 사각형으로 투영한다. 측면은 수직을 유지하고 상판은 직선과 연결점을 유지한다. TV 이미지 순서는 [1,0,2,3], 대형 식탁은 [1,0,3,2]로 명시한다. 원형 받침 물품은 셀 중앙에 맞춘다. 테라스도 동일 렌더러를 사용하며 저장 좌표·가격은 그대로다.

`sprite-geometry.test.mjs`는 바닥 접점, 상판 연결, 수직면과 역변환을 검사한다. `verify-sprite-planes.cjs`는 본관 전체 21종/84방향 실제 이미지 검사를 수행한다. `tv-floor-check.cjs`는 실제 거실 TV 네 방향·선택·무료 이동·좌표 보존을 확인한다. 자산 재제작 프롬프트: assets/house/plane-registration-prompts.json.

확대/축소 조작부는 테라스와 실내 모두 캔버스 밖 상단 툴바에 둔다. 본관 진입 시 거실, 2층 전환 시 다이닝 홀을 자동 선택한다. 구매 비활성 사유(불러오기/잔액 연결 실패/실내 서버 미지원/배치 진행)는 상단에 표시한다. 앱에서 실내 서버 미지원이라고 표시되면 통합 Code.gs를 새 버전으로 배포해야 한다.

소파/커피 테이블은 1층 바닥 각도로 다시 제작한 4방향 시트를 사용한다. 알파 이미지에서 가장 낮은 불투명 다리 끝을 읽어 footprint 앞 모서리에 맞춘다. 선택·배치 footprint는 이미지 뒤에 그린다. 커피 테이블 수정본은 본관 전용이며 기존 테라스 이미지는 유지한다. 제작 프롬프트는 assets/house/ground-contact-prompts.json에 있다.

1층은 `FLOOR_ONE_PLANES`의 공간별 원점/동일 길이 타일 축으로 격자·가구·터치 좌표를 함께 투영한다. 저장된 논리 좌표와 가구 ID/가격은 유지한다. A룸의 앞벽에 가려지는 칸과 계단 그림 영역은 구매·이동 대상에서 제외한다. 2층 좌표 변환은 유지한다.

테스트 URL: `test.html`. 최초 테스트 잔액은 10,000 AST이며 실제 계정 지갑과 분리한다. `mode=test`는 테라스/본관 이동에도 유지되고 동일한 `ast-home-test-v1` 브라우저 저장소의 잔액과 배치를 공유한다. 테스트 초기화 버튼은 해당 테스트 저장소만 비우며, 다시 10,000 AST로 시작한다.

테라스 문에는 ENTER · 1층 버튼, 실내 계단에는 2층 올라가기/1층 내려가기 버튼, 1층 입구에는 테라스로 나가기 버튼이 있다. 이동 자체에는 비용이 없고 가구 구매 확정에만 표시된 AST를 차감한다.

기존 입구 거실의 문에 있는 ENTER 버튼으로 들어간다. URL은 기존 index 경로에 `scene=mansion`을 추가하여 AST WebView의 허용 경로를 유지한다.

## 구성

- 1층: 넓은 거실, 2시 방향 A/B/C 연습실, 7시 방향 입구, 단일 일자 계단.
- 2층: 넓은 다이닝 홀, 5시 방향 계단 도착 지점.
- 영역을 선택하면 해당 영역에 맞는 구매 목록이 열린다.
- 연습실: 피아노, 마이크, 악보 거치대, 연습 의자, 악보 책장, 화분, 스피커(120), 연습용 탁자(90), 기타(110), 드럼(280 AST).
- 거실: 클래식 소파, 낮은 테이블, 책장, 화분, LCD TV와 거실장(220), 클래식 암체어(100), 장스탠드(65 AST).
- 2층: 대형 식탁, 다이닝 의자, 화분, 암체어, 장스탠드, 다이닝 수납장(140 AST).
- 문과 계단 위 이동 버튼은 확대·화면 드래그를 따라간다. 바닥 이동 안내선 없이 문과 계단 버튼으로 이동한다.
- 식탁을 선택하고 '식탁 위 꾸미기'를 누르면 과일, 티 세트, 빵 바구니 구매가 가능하다.
- 이동/회전 및 O/X 확정, 확대·화면 드래그, 누적 기여도와 구매자/구매시각이 유지된다.

새 가구 가격은 시제품 기본값이며 HOUSE_ITEMS와 서버 HOME_TYPES에서 함께 관리한다.

## 저장

기존 state.json을 사용한다. 기존 입구 거실 가구에는 area가 없다. 본관 가구는 area=hall/roomA/roomB/roomC/dining을 가진다. 음식은 식탁 UID를 parent로 가지며 식탁의 로컬 상판 좌표로 저장한다. 식탁을 이동·회전하면 음식도 함께 따라간다.

기존 아스트 지갑 서버에 확장 규칙을 추가해야 실제 구매가 가능하다. `integration/AST-HOME-EXPANSION-COMBINED.gs`를 기존 Apps Script 프로젝트 Code.gs에 통째로 교체하고 중복 HomeGame.gs 파일은 제거한 뒤 새 버전으로 배포한다. 기존 APP_KEY/GITHUB_TOKEN 및 지갑 데이터는 유지한다. 이 코드에는 기존 지갑 조회/수령 정책, 중복 구매 방지 및 중단 복구, 확장 영역/상판 배치 검증이 포함된다.

서버가 features.mansion=1을 응답하기 전까지 실제 공동 모드에서 새 공간의 구매는 비활성화된다. 기존 거실과 기존 잔액은 그대로 이용할 수 있다. 서버 업데이트 전 새 공간은 둘러보기만 가능하다.

## 자산

assets/house에 1·2층 배경과 17종 4방향 PNG 시트를 저장한다. 승인한 계단 배경은 floor-1-approved-v5.png이다. 이미지 제작에는 built-in image_gen을 사용했다. 프롬프트는 assets/house/prompts.json 및 catalog-v2-prompts.json, 바닥 설계는 house-layout.mjs와 floor-*-blueprint.svg에 보관한다.

새 8종 가구는 서버가 features.furniture=2를 응답해야 공동 모드 구매가 활성화된다. 최신 통합 Code.gs로 교체 후 새 버전 배포가 필요하다. 로컬 체험에서는 바로 이용할 수 있다.

## 검증

`node house.test.mjs`: 셀 변환, 방향, 영역 카탈로그, 충돌, 회전, 계단 점유, 식탁 상판 경계.
`node integration/server.test.cjs`: 잔액 차감/복구 및 확장 서버 검증.
`node house-browser-check.cjs`: 로컬 체험의 층 전환·연습실 구매·식탁/음식·저장·모바일 메뉴. 로컬 서버 4181 사용.
